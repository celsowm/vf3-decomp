# 0x8C08C788 — guarded state update

Baseline span: `0x8C08C788..0x8C08C7FF` (120 B), including its matching
`rts` at `0x8C08C7FC`.

The function first checks four flag words in the `r14` record, then compares
signed halfwords at `object+30` and `object+106`. If their absolute difference
is below `0x2000`, it returns zero. Otherwise it reads an 8-bit bound at
`r4+58`, advances the LCG state at `0x0C29BD74`, and calls the unsigned
remainder helper at `0x8C042E44`. A zero remainder writes `14` at `r14+44` and
returns one. The helper's zero-bound arm writes `0x44E` at `0x0C1A5A60`.

## Oracle coverage

`vf3_c788_ram.txt` captures four RAM windows, including the global error
word. The ordinary state-30-to-44 and high-sample captures exercise the
natural guard exits. Three one-shot oracle-entry mutations in the local
Flycast trace hook enabled otherwise rare paths while keeping the executed
SH-4 body unchanged:

- force mode 1 clears the record guards, sets the compared halfword to zero,
  and seeds the LCG with zero (zero remainder / state update);
- force mode 2 uses seed one with the normal bound (nonzero remainder);
- force mode 3 sets the bound to zero (error helper).

The entry RAM snapshot includes each mutation. Each of the four `.cases` sets
passes 64 paired register and RAM replays through `build/vf3c788.exe`. The
forced capture hook is local to the ignored Flycast worktree; the golden
capture folders under `extract/analysis/` are also ignored by Git.
