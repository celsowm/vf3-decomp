# Thirteenth C coverage batch

Generates two more adapter modules and promotes **8 no-owner partial-body-cover
leaves**. These are entries whose bodies contain no PC that any existing
adapter owns, so calls fall through to `vf3_matrix_adapter` which rejects
them. Each new adapter was generated by running `translate_adapters.py`
against the existing captures with a broader watch list, then wired into
the dispatch chain and verified under `VF3_STRICT_REPLAY=1`.

Both new adapters pass `matrix_family: N/N cases match (0 skipped) - PASS`

## How this advances the decomp

The advance plan in `docs/re/advance_plan.md` separates "100% body cover" (the
full promotion gate for Phase 3 named closures) from "passes strict replay"
(the standard promotion gate for capture-driven ports). The eleventh batch
generated the first two new adapters; this thirteenth batch generates two
more. Each generation cycle shrinks the "no-owner partial cover" cohort and
exposes captures that already existed but had no adapter serving them.

The 5 partial-cover failures from the twelfth batch (`0x8C04853A` 549/989,
`0x8C0C7810` 0/1, `0x8C0460A6` 36/128, `0x8C08B5DC` 16/37,
`0x8C03B364` 0/24) are still failing — they require either wider input
seeding or a body-cover extension that the current capture corpus cannot
supply. They remain uncredited.

The remaining 3 Phase 3 named closures (`0x8C09C1F4` 2084B, `0x8C0C438E`
1694B, `0x8C0C321E` 1574B) are parked behind seed calibration; the plan's
next step is to re-run the pilot against a verified scratch page and
measured masks.
